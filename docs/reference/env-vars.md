# Environment variables

Every `SCHEDULER_*` variable the daemon reads through `os.Getenv`/`os.LookupEnv` — plus `SCHEDULER_URL`, which the in-tree `scheduler-query` CLI reads and the same sweep therefore covers — derived from the code:

```
grep -rn "os.Getenv\|os.LookupEnv" internal cmd --include=*.go | grep -v _test.go | grep -oE 'SCHEDULER_[A-Z0-9_]+' | sort -u
```

Every name that command prints is documented below — each in a table row except `SCHEDULER_FOREMAN_ROUTING_MODE`, which has its own subsection under spawner defaults — and the one non-daemon knob, `SCHEDULER_URL`, is marked CLI-only. Do **not** add an `awk -F: '{print $3}'` field split to that pipeline: the `:=` in `if v := os.Getenv("…")` lines is a colon, so the variable name lands in a later field and five names silently disappear from the output. `--show-config` prints its own inventory of the `SCHEDULER_*` overrides it tracks plus the masked operator token; this page is the superset, including the spawner/env-only knobs that surface never prints and the live-proof test variables in the Crier section. One name that pipeline cannot see: `SCHEDULER_IDLE_INTERVENTION` is held in a Go const (`internal/scheduler/idle_intervention.go:29`) rather than a string literal at the `os.Getenv` call site, so the sweep never prints it — it is documented below from that const and its resolver.

## The env layer

- **When env is read:** once, at process boot (`cmd/schedulerd/main.go` resolves all `SCHEDULER_*` overrides after flag parsing, before `--show-config`/`--schema` print — so both surfaces show effective values). Exceptions that read later: `SCHEDULER_WAVE_TICK_TIMEOUT` (at each wave spawn), `SCHEDULER_CIRCUIT_CMD`/`SCHEDULER_ROUTER_CMD`/`SCHEDULER_FOREMAN_*` (at spawner construction), `SCHEDULER_IDLE_INTERVENTION` (at spawner construction, `internal/scheduler/spawn.go:376`), and the clock vars (after the early-exit commands).
- **Precedence for flag-backed knobs:** CLI flag > env var > TOML (`schedulerd.toml` via the default-guard pattern in main.go — a TOML value applies only while the flag sits at its default) > flag default. The same chain holds on the library config path (`internal/config.LoadConfig`: defaults < TOML < env, flags applied by the caller). Since TR-162 it also holds on the daemon boot path: `internal/config.LoadRootConfig` applies the `SCHEDULER_*` env layer over the decoded TOML (previously it returned the raw decode and env > TOML never held there). Caveat: not every env block is flag-guarded — some are applied unconditionally after `flag.Parse`, so for those a set env var also overwrites an explicit flag (`SCHEDULER_BOARD_STASIS_GATE`, `SCHEDULER_DISABLE_TICK_PUSH`, the two session watchdogs). Each row below states the chain that is real for its knob.
- **TOML coverage is partial on the daemon path.** main.go's default-guard block applies only these TOML keys: `[scheduler]` `weight_budget`, `gateway_response_timeout`, `slot_patience`, `tasks_pacing`, `spawn_mem_limit_mb`, `load_gate_threshold`, `auto_disable_*`, `failure_window`, `metered_budget_enabled`, `session_silence_grace`, `session_poll_loop_min_ticks`, `[api]` `read_timeout` / `operator_token` / `operator_user` / `operator_password`, plus blackout windows and the fleet seed sections. The TOML keys `daemon.db_path`, `daemon.listen`, `min_interval`, `max_interval`, `num_levels`, `max_concurrent`, `tick_timeout`, `gateway.url`, `gateway.foreman_home`, and `duckbrain.*` are declared in `--schema` output but main.go never applies them — for those knobs env is the only layer between the flag and its default. Rows below state the real chain.
- **Invalid values:** most overrides WARN and keep the current value — a garbage value must never silently change or disable a deadline, cap, or gate (`SCHEDULER_GATEWAY_RESPONSE_TIMEOUT`, `SCHEDULER_SLOT_PATIENCE`, `SCHEDULER_TASKS_PACING`, `SCHEDULER_API_READ_TIMEOUT`, `SCHEDULER_LOAD_GATE_THRESHOLD`, `SCHEDULER_SPAWN_MEM_LIMIT_MB`, `SCHEDULER_METERED_BUDGET_ENABLED`). A few are silently ignored when unparseable (`SCHEDULER_FAILURE_WINDOW`, `SCHEDULER_BUDGET`, `SCHEDULER_AUTO_DISABLE_*`, the int fields in `applyEnvOverrides`).
- **Sim mode:** `SCHEDULER_TIME_MODE=sim` is REFUSED at boot (fatal) unless `--simulate` is also set — a stray env var must never put the live fleet on a fake clock. See [clock-modes.md](clock-modes.md).
- **`${VAR}` interpolation:** `${API_SERVER_KEY}`-style placeholders inside `schedulerd.toml` are expanded from the process environment before TOML decode (`internal/config`); unknown names expand to empty. This is a second way env reaches the config — it writes the TOML layer's value, not the env layer's.

## Spawner defaults and model selection

`SCHEDULER_FOREMAN_ROUTING_MODE` (SCHED-HARNESS-001) is resolved at boot
(env > TOML `[scheduler] foreman_routing_mode` > `router`) and frozen at
spawner construction. Unset/`router` preserves existing routing. `fixed`
bypasses task-router only for canonically classified foreman lanes and
requires both explicit project `model` and `provider` (blank arms are refused
before gateway or exec). The foreman route contains exactly that pair:
project/namespace chains, idle tiers, project fallback and global defaults
are not spliced in, and 401/403 cannot advance to another pair. Satellite
and empty/unknown packed lane classes retain existing routing. Invalid mode
values fail loudly; values are exact (case/whitespace are not normalized).
`--schema`, `--show-config` and `/api/v1/config` expose the policy; unlike
the older TOML-backed knobs, this policy resolves before `--show-config`.
There is no CLI flag and no worker-dispatch or harness connector change.
The global model defaults below apply to router policy, not fixed foremen.

| Env var | Effect | Default when unset | Precedence |
|---------|--------|--------------------|------------|

## Crier bus (federation visibility + work dispatch)

The Crier bus client (REMOTE-004) publishes tick-terminal and lane-state events to the fleet relay and carries the work-dispatch leg (SCHED-GAP-1710): a lane whose row in `dispatch-targets.jsonl` names an agent has its ticks handed to that agent over the relay's durable inbox. Behavior, wire contract and failure vocabulary are owned by [dispatch-spec.md](../dispatch-spec.md); the commented `[crier]` block in [config.example.toml](../../config.example.toml) owns the TOML layer. These rows state only what each env var does — resolved at `cmd/schedulerd/main.go:656-692`, following the REMOTE-003 identity precedent: TOML `[crier]` base layer, `CRIER_*` env overrides on top, deliberately NO CLI flag layer (credentials never live in argv, GAP-038).
